Hackathon phone guide

Your team has one real Android phone for the event, controlled through an HTTP API. Every touch goes through a hardware board (ESP32) plugged into the phone, so it acts like a real finger. Drive the phone step by step, hand a goal to our AI phone agent, and replay a successful run as a recipe without the AI.

The key stays in this browser tab: it is not saved and not sent anywhere. To test it from a browser, open /hack/v1/docs, click Authorize, paste the key, then run GET /phone/status with Try it out.

1. Connect (5 minutes)

The server uses its own certificate authority. Download hack-root-ca.crt (button above) into your working folder and point your tools at it.

export HACK=https://172.26.0.32/hack/v1
export KEY=YOUR_TEAM_KEY
export CA=$PWD/hack-root-ca.crt

curl --cacert $CA -H "Authorization: Bearer $KEY" $HACK/phone/status

Expected answer:

{"ok": true, "data": {"device_id": "team-3-phone", "online": true, "ble_linked": true, "busy": null,
 "screen": {"w": 1080, "h": 2400}, "rotation": 0, "current_app": null}}
ToolTrust the CA with
curl (Linux / macOS)--cacert hack-root-ca.crt
curl.exe (Windows)--cacert hack-root-ca.crt --ssl-no-revoke (our CA publishes no revocation list)

2. How it works

  • One key = one phone. Every phone call is /phone/…; your key decides which phone. You only ever see your own phone, tasks, recipes and targets.
  • Envelope. JSON answers are {"ok": true, "data": …} or {"ok": false, "error": {"code": "…", "message": "…"}}. Screenshots (image bytes) and live streams (server-sent events) are the exceptions.
  • Two ways to tap. A screen point in pixels ({"x": 540, "y": 1200}), or a target: a named box you define once; the tap lands at its centre, so your scripts keep working if you re-calibrate. See section 4.
  • Manual mode (emergencies). The team console's Manual screen mode is a smooth scrcpy view of your phone; switch on control only if you are stuck. That input goes over adb instead of the board, it is logged, and it is blocked while your agent or recipe run holds the phone.
  • Inputs are real. Each tap / type / key goes through the board and returns {"transport": "ble", "ms": …}. Sometimes the board doesn't confirm (504 INPUT_UNCONFIRMED): the action may or may not have happened, so look at the screen before retrying.
  • One job at a time. While an agent task or recipe run is active, your own inputs get 409 DEVICE_BUSY. Wait or cancel it.

3. Look at the phone

# screenshot (PNG; add ?format=jpeg&max_width=540 for a small one). Max 1 per second.
curl --cacert $CA -H "Authorization: Bearer $KEY" "$HACK/phone/screenshot" -o screen.png

# screen size and density / rotation
curl --cacert $CA -H "Authorization: Bearer $KEY" $HACK/phone/geometry

Live view (read-only)

GET /phone/live is a server-sent-event stream of about 2 JPEG frames per second (event: frame with jpeg_b64). While your agent task runs it shows the agent's own view; otherwise it polls the phone. It doesn't count against your screenshot limit. Max 3 open streams per team.

# live.py: keeps latest.jpg updated with the phone screen (Ctrl+C to stop)
import base64, json, requests

H = {"Authorization": "Bearer YOUR_TEAM_KEY"}
with requests.get("https://172.26.0.32/hack/v1/phone/live", headers=H, stream=True,
                  verify="hack-root-ca.crt", timeout=(10, 60)) as r:
    event = None
    for line in r.iter_lines(decode_unicode=True):
        if line.startswith("event:"):
            event = line[6:].strip()
        elif line.startswith("data:") and event == "frame":
            frame = json.loads(line[5:])
            open("latest.jpg", "wb").write(base64.b64decode(frame["jpeg_b64"]))
        elif line.startswith("data:") and event == "status":
            print("phone:", line[5:])

Activity

GET /activity lists your latest calls and task changes, newest first; GET /activity/stream streams them live. It's the quickest way to see what really happened.

4. Drive it yourself

Keys, typing, swiping, apps

A="Authorization: Bearer $KEY"; J="Content-Type: application/json"

curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/phone/key   -d '{"key":"home"}'
#   keys: home back enter tab esc search volume_up volume_down

curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/phone/type  -d '{"text":"hello world"}'
#   printable ASCII only; for a new line send the key "enter"

curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/phone/swipe -d '{"direction":"up","distance":"medium"}'
#   direction: up down left right   distance: short medium long

curl --cacert $CA -H "$A" $HACK/phone/apps                  # the apps you may open
curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/phone/app-start -d '{"package":"com.android.settings"}'
curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/phone/app-stop  -d '{"package":"com.android.settings"}'

Allowed apps: com.facebook.katana, com.android.settings, com.google.android.apps.photos, com.google.android.GoogleCamera.

Tapping a point

curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/phone/tap        -d '{"x":540,"y":1200}'
curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/phone/long-press -d '{"x":540,"y":1200,"ms":1200}'

Pixels of the screenshot (see /phone/geometry). A point outside the screen gets 422 TARGET_OUTSIDE_SCREEN.

Tapping a named target (recommended for scripts)

  1. Take a screenshot and find the element in screenshot pixels (check /phone/geometry; typically 1080 × 2400). Any image viewer that shows pixel positions works.
  2. Save it as a named box: top-left corner x, y plus width w and height h. 
    curl --cacert $CA -H "$A" -H "$J" -X PUT $HACK/phone/targets/settings-search \
     -d '{"x":60,"y":310,"w":960,"h":120,"app":"com.android.settings","description":"search bar"}'
  3. Check where it would tap. This does not tap: 
    curl --cacert $CA -H "$A" -X POST $HACK/phone/targets/settings-search/test
  4. Tap it, or long-press it: 
    curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/phone/tap        -d '{"target":"settings-search"}'
curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/phone/long-press -d '{"target":"settings-search","ms":1200}'

Target names: lowercase letters, digits, . _ -, max 64 characters. GET /phone/targets lists yours; DELETE /phone/targets/{name} removes one. A box must be inside the screen and at least 8 px wide and high.

Upload media to the phone

curl --cacert $CA -H "$A" -X POST $HACK/phone/media -F "file=@photo.jpg"
# -> {"device_path": "...", "bytes": ..., "mime": "image/jpeg"}   it appears in the phone's gallery

JPEG, PNG, WebP or MP4, up to 50 MB. GET /phone/media lists your uploads.

5. The AI agent

Give a goal in plain language. Our phone agent (a vision LLM) looks at the screen and acts through the same board.

curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/tasks \
     -d '{"goal":"Open the Settings app and tell me the Android version of this phone.","mode":"flash"}'
# -> {"ok":true,"data":{"id":"<task id>","status":"queued",...}}

curl --cacert $CA -H "$A" $HACK/tasks/<task id>          # queued -> running -> idle / succeeded / failed
curl --cacert $CA -H "$A" $HACK/tasks/<task id>/events   # every step, action and screenshot
  • mode: flash is fast; pro is slower and adds an independent check of the answer (verified, verdict).
  • Structured output: "output_format": "json", "output_schema": {…} puts the result in result_data.
  • status: idle means the agent finished and waits a few minutes for a follow-up: POST /tasks/{id}/messages {"text": "now also …"}. POST /tasks/{id}/cancel ends it.
  • If the agent asks for permission, the task becomes awaiting_approval: GET /approvals?status=pending, then POST /approvals/{id} {"approved": true}.
  • GET /tasks/{id}/stream streams the events live; GET /tasks/{id}/screenshots/{n} returns step screenshots.
  • For scale: the Android-version goal above takes about 5 steps and 1½ minutes.

Run record: your proof

curl --cacert $CA -H "$A" $HACK/tasks/<task id>/run-record

Steps (each with its transport), evidence, model calls and tokens, wall-clock time, and an outcome:

  • confirmed: succeeded with independent evidence (a pro verdict, or a replay whose success check passed);
  • uncertain: finished but not proven;
  • failed: failed or cancelled.

6. Recipes: redo it without the AI

A successful agent run can be compiled into a recipe: the same steps, replayed directly on the phone with 0 LLM tokens. If the screen has changed, the agent repairs just that step (allow_heal) and saves a new version.

# 1. compile a finished task (status "compiling", then "draft" after ~30 s; poll GET /recipes/<id>)
curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/tasks/<task id>/recipe -d '{"name":"android version"}'

# 2. activate the version
curl --cacert $CA -H "$A" -H "$J" -X PATCH $HACK/recipes/<recipe id> -d '{"activate_version":1}'

# 3. replay: returns a task with run_mode "replay"; poll it like any task and check "tokens": 0
curl --cacert $CA -H "$A" -H "$J" -X POST $HACK/recipes/<recipe id>/run -d '{}'

GET /recipes lists yours. GET /recipes/{id}/versions/{v} shows the steps. You can edit them with PATCH /recipes/{id} {"body": …}, which saves a new version.

9. Python starter

# pip install requests
import requests

BASE = "https://172.26.0.32/hack/v1"
S = requests.Session()
S.headers["Authorization"] = "Bearer YOUR_TEAM_KEY"
S.verify = "hack-root-ca.crt"

def api(method, path, **kw):
    r = S.request(method, BASE + path, timeout=60, **kw)
    if r.headers.get("content-type", "").startswith("application/json"):
        body = r.json()
        if not body.get("ok"):
            raise RuntimeError(f"{r.status_code} {body['error']['code']}: {body['error']['message']}")
        return body["data"]
    r.raise_for_status()
    return r.content            # screenshots

print(api("GET", "/phone/status"))
api("POST", "/phone/key", json={"key": "home"})
open("screen.png", "wb").write(api("GET", "/phone/screenshot"))
task = api("POST", "/tasks", json={"goal": "Open Settings and tell me the Android version."})
print("task", task["id"], task["status"])
